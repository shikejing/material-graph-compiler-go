# material-graph-compiler-go

把由节点与连线组成的材质图编译为可供渲染侧消费的着色程序。整个编译过程在
本地进程内完成，不依赖任何外部服务；同一份输入的结论与错误在本地稳定复现。

## 包结构

| 包 | 职责 |
| --- | --- |
| `graph` | 材质图数据模型（节点/端口/连线）、值类型与隐式转换、内容指纹 |
| `nodelib` | 版本化节点库：节点定义、端口签名、版本间迁移规则 |
| `compiler` | 整图校验、确定性代码生成、编译期优化、增量编译 |
| `cache` | 并发安全的有界 LRU 缓存 + 单飞去重 |
| `service` | 面向渲染侧的编译服务：批量请求、失败隔离、结果查询 |

## 编译语义

### 图模型与校验

- 节点带输入/输出端口，端口有类型与默认值；输入端口未连线时取覆盖值
  （`Node.Overrides`），否则取端口默认值。
- 连线两端类型必须兼容（`nodelib.Compatible`）：同类型恒兼容；
  `float→vec2/vec3/vec4/color`、`int→float`、`vec3→vec4/color` 可隐式转换。
- 校验是**整体**的：出现环、连线指向不存在的端口、端口类型不匹配、
  必填输入缺失、节点类型未知中任意一种，整张图被拒绝，返回
  `*graph.Error`，其中每条 `Diagnostic` 都定位到具体节点与端口
  （诊断码：`CYCLE` / `PORT_NOT_FOUND` / `TYPE_MISMATCH` /
  `MISSING_INPUT` / `UNKNOWN_NODE_TYPE` / `DUPLICATE_NODE` /
  `DUPLICATE_INPUT_EDGE`）。校验失败时不产出任何部分结果。
- 诊断按 `(节点, 端口, 诊断码)` 排序，顺序确定。

### 确定性输出

同一张图在任意节点遍历顺序与任意并发度下，产出的 `Program.Source`
逐字节一致。保证手段：

- 拓扑排序使用 Kahn 算法，就绪集按节点 ID 字典序取最小；
- 所有 map 迭代（覆盖值、连线、诊断）在输出前一律排序；
- 生成变量名只由节点 ID 与端口名派生（`v_<node>_<port>`）；
- 输出不含随机标识、时间戳或任何遍历顺序带来的内容。

### 优化策略

`Options.Optimize` 开启两类编译期优化，优化前后对外语义等价，
可观测的输入输出契约（输出节点、输出端口、最终表达式求值结果）不变：

1. **常量折叠**：全部输入都是编译期常量且节点定义携带 `Fold` 规则的
   节点被替换为常量，常量改写为下游端口的覆盖值，迭代至不动点。
   输出节点永不折叠。
2. **不可达消除**：从输出节点沿连线反向不可达的节点被移除。

每个被消除的节点都会在 `Program.Eliminated` 中记录原因
（`constant-folded: ...` / `unreachable: ...`），按节点 ID 排序。

### 增量重编

`compiler.CompileIncremental` 为每个节点计算**依赖哈希**
（节点内容 + 各输入来源的依赖哈希 + 节点库版本指纹），按拓扑序推导；
依赖哈希未变的节点直接复用节点级行缓存中的代码行，只有受影响
（自身或上游变化）的节点重新生成。由于每行内容只取决于该节点的依赖
闭包，且装配顺序与全量编译同为确定拓扑序，**增量产出与全量重编逐字节
一致**。`Reused` / `Rebuilt` 分别列出被复用与被重编的节点。

### 节点库版本化与迁移

- 节点库按整数版本注册（严格递增）。缓存键包含库版本指纹，不同版本的
  编译结果互不污染；已按旧版本产出的结果在库升级后依然可复现。
- `nodelib.MigrateGraph` 把旧图逐版本迁移到新版本，规则确定：
  - `RenamedPorts`：连线与覆盖值中的旧端口名改为新名；
  - `RemovedPorts`：被删端口的连线与覆盖值一并丢弃；
  - `NewDefaults`：新增端口用声明值补全为覆盖值，钉住旧行为
    （例如默认值发生变化的端口）；
  - 新版本中必填输入（无默认值）若无连线、无覆盖、无迁移规则，
    迁移被拒绝。
- 无法自动兼容的升级（如节点类型被删除且无迁移规则、输出端口被删除）
  返回 `*MigrateError` 并列出全部原因；**原图不被修改**，已产出的
  编译结果不受影响。降级（新版本→旧版本）一律拒绝。

## 并发与缓存

### 缓存键

缓存键只由**图内容指纹**（`graph.Graph.Key`，与切片顺序无关）与
**节点库版本指纹**（`nodelib.Library.VersionKey`）加优化开关组成，
不含请求 ID、时间戳等任何请求侧信息。

### 并发语义

- `cache.Cache.GetOrCompute` 对同一键做单飞合并：并发请求同一材质图
  只计算一次，其余等待者拿到同一份完整结果；
- 读者要么拿到完整结果要么拿到错误，绝不返回半成品；
- 计算失败的结果不写入缓存（可重试），但会分发给当前等待者。

### 缓存失效规则

- 图内容任何变化（节点、连线、覆盖值、输出声明）都会改变图指纹，
  旧条目自然失效（不会再被命中），无需显式失效；
- 节点库升级改变版本指纹，旧版本条目保留但不再被新请求命中；
- 缓存为有界 LRU：程序缓存容量为 `cacheCapacity`，节点行缓存为其
  16 倍；超容时淘汰最近最少使用项，**占用不随请求量无界增长**；
- 需要主动清理时可调用 `cache.Cache.Invalidate(key)`。

## 部分失败与诊断

- `service.CompileBatch` 并发处理一批请求，单个节点参数非法或单张图
  编译异常只影响该请求的结果，同批其他请求正常完成；
- 每个 `Result` 成功（`Program`）与失败（`Err` + `Diags`）二选一，
  诊断定位到节点与端口；
- 所有请求的结果（含失败）都可通过 `service.GetResult(id)` 查询。

## 测试

```sh
go test ./...          # 全部测试
go test ./... -race    # 含竞态检测
```

覆盖：环检测、类型不匹配、端口缺失、确定性（乱序/并发）、常量折叠与
不可达消除、增量重编与全量一致性、节点库升级迁移（改名/删端口/
默认值钉住/拒绝不兼容）、并发缓存单飞与有界增长、批量失败隔离。
